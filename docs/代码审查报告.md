> 说明：受沙箱文件权限限制，本次未执行 `mvn compile` / 启动验证，结论均来自代码静态分析，涉及数据库表结构的地方已标注「需核实」。

## 二、做得好的地方（可写进简历的部分）

1. **分层清晰、职责单一**：Controller 只做参数接收与结果包装，业务在 Service，SQL 在 Mapper；没有出现 Controller 里写 SQL 的常见问题。
2. **统一响应结构**：`Result` 静态工厂（`success()` / `success(data)` / `error(msg)`）搭配 `PageResult<T>{total, rows}`，前端消费成本低。
3. **全链路 `#{}` 预编译占位**：所有 XML 与注解 SQL 均未使用 `${}` 拼接，从根上规避了 SQL 注入。
4. **动态 SQL 用得规范**：`<if>` + `<where>` + `<set>` + `<foreach>`，员工分页的姓名/性别/入职区间为可选条件，`update` 只更新非空字段；`insertBatch` 用 `foreach` 一次批量插入工作经历，避免 N 次往返。
5. **嵌套 resultMap 解决一对多**：`<collection>` 把 `emp` 与 `emp_expr` 一次 JOIN 装配成 `exprList`，消除了「先查员工再循环查经历」的 N+1。
6. **JWT 无状态鉴权链路完整**：登录签发 → 拦截器校验 → `ThreadLocal(CurrentHolder)` 透传当前登录人 → `afterCompletion` 清理，且**清理写在拦截器里而不是业务里**，避免线程池复用造成用户串号。
7. **AOP 操作日志设计到位**：自定义 `@OperateLog` 注解 + `@Around` 环绕，记录类名/方法名/参数/返回值/耗时；用 `AopUtils.getTargetClass()` 规避 CGLIB 代理类名；参数序列化前过滤 `ServletRequest`/`MultipartFile`/`BindingResult`；超长内容按 2000 字符截断；**日志写入失败被 try-catch 吞掉，不影响主业务**——这几点都是真实工程经验，不是教程代码。
8. **对外部依赖做了封装**：OSS 上传抽成 `AliyunOSSOperator` + `@ConfigurationProperties`，凭证走环境变量而非硬编码，`OSSClient` 用 try-with-resources 释放。
9. **分页统一走 PageHelper**，没有手写 `limit` 与 `count` 两套 SQL，减少维护面。
10. **违纪扣分用数据库原子自增**（`violation_score = violation_score + #{score}`）而非「查出来 +1 再写回」，天然规避并发丢失更新。

<!-- 2. 查询列白名单，别用 e.* -->
<select id="list" resultType="com.mww.pojo.Emp">

### P0-2 密码未加盐哈希，登录直接明文比对

**位置**：[EmpMapper.xml:96-98](tlias-web-management/src/main/resources/com/mww/mapper/EmpMapper.xml#L96-L98)

```sql
select * from emp where username = #{username} and password = #{password}
```

数据库里存的就是明文（`application.yml` 里能看到 `password: 1234` 这类风格）。一旦库被拖走，所有密码立刻泄露。同时登录接口没有失败次数限制、没有验证码，可被暴力破解。

**修复**：引入 `spring-boot-starter-security-crypto` 或 BCrypt，注册/改密时 `BCrypt.hashpw`，登录时 `BCrypt.checkpw`；`selectByUsernameAndPassword` 改为 `selectByUsername` 后由代码比对。

> 这条是简历面试的「高频送分题」，改掉之后就是可讲的技术点。

### P0-3 员工新增写日志的事务失效（`finally` + 同事务）

**位置**：[EmpServiceImpl.java:52-73](tlias-web-management/src/main/java/com/mww/service/impl/EmpServiceImpl.java#L52-L73)、[EmpLogServiceImpl.java:18-20](tlias-web-management/src/main/java/com/mww/service/impl/EmpLogServiceImpl.java#L18-L20)

```java
@Transactional(rollbackFor = {Exception.class})
public void save(Emp emp) {
    try {
        empMapper.insert(emp);
        ...
    } finally {                                  // ← 日志写在 finally
        EmpLog empLog = new EmpLog(null, LocalDateTime.now(), emp.toString());
        empLogService.insertLog(empLog);         // ← 加入同一个事务
    }
}
```

`insertLog` 没有声明任何传播行为，默认 `REQUIRED`，会加入外层事务。于是：

- 业务失败 → 异常抛出 → `finally` 先写日志 → 事务整体回滚 → **日志也一起没了**，恰好丢掉最需要的那条失败记录；
- 业务成功 → 日志在 commit 之前写入，commit 失败同样丢日志。

`EmpLogServiceImpl` 里 `import` 了 `Propagation` 和 `Transactional` 却没用——说明本来想加 `REQUIRES_NEW`，漏了。

**修复**：

```java
@Transactional(propagation = Propagation.REQUIRES_NEW)
public void insertLog(EmpLog empLog) { empLogMapper.insert(empLog); }
```

并把 `finally` 改为「成功后再记」，或改用 `TransactionSynchronizationManager.registerSynchronization` 在 `afterCommit` 里写。

**附带问题**：`emp.toString()` 是 Lombok `@Data` 生成的，会把 `password` 明文写进 `emp_log.info`，与 P0-1 同源。脱敏后再落库。

### P0-4 修改员工：两表写操作没有事务，失败即数据丢失

**位置**：[EmpServiceImpl.java:87-99](tlias-web-management/src/main/java/com/mww/service/impl/EmpServiceImpl.java#L87-L99)

```java
@Override                       // ← 没有 @Transactional
public void update(Emp emp) {
    empMapper.updateById(emp);
    empExprMapper.deleteByEmpIds(Arrays.asList(emp.getId()));   // 先删
    if (!CollectionUtils.isEmpty(exprList)) {
        empExprMapper.insertBatch(exprList);                    // 再插
    }
}
```

删旧经历与插新经历之间没有任何保护。若 `insertBatch` 抛异常（字段超长、日期非法、连接抖动），**旧工作经历已被物理删除**，用户提交失败却永久丢失数据。

**修复**：加上 `@Transactional(rollbackFor = Exception.class)`（与 `save` 保持一致）。

### P0-5 修改班级会把 `create_time` 清空

**位置**：[ClazzMapper.xml:10-13](tlias-web-management/src/main/resources/com/mww/mapper/ClazzMapper.xml#L10-L13)、[ClazzServiceImpl.java:45-49](tlias-web-management/src/main/java/com/mww/service/impl/ClazzServiceImpl.java#L45-L49)

```xml
<update id="update">
    update clazz set name = #{name}, ..., create_time = #{createTime}, ...
    where id = #{id}
</update>
```

更新时前端只传业务字段，`ClazzServiceImpl.update` 也只 set 了 `updateTime`，于是 `createTime` 为 `null`，SQL 把创建时间**覆盖成 NULL**。如果该列是 `NOT NULL`，则直接报错，编辑功能不可用；如果可空，历史数据被静默破坏。

**修复**：`update` 里删掉 `create_time`；同时把整体覆盖改为 `<set>` 动态更新，避免前端漏传字段被写成 null。

### P0-6 文件上传未做类型/内容校验，且扩展名解析会抛异常

**位置**：[UploadController.java:39-43](tlias-web-management/src/main/java/com/mww/controller/UploadController.java#L39-L43)、[AliyunOSSOperator.java:38](tlias-web-management/src/main/java/com/mww/utils/AliyunOSSOperator.java#L38)

```java
String newFileName = UUID.randomUUID() + originalFilename.substring(originalFilename.lastIndexOf("."));
```

- 文件名不含 `.` 时 `lastIndexOf` 返回 `-1`，`substring(-1)` 抛 `StringIndexOutOfBoundsException` → 500；
- 没有任何白名单，`.jsp/.html/.svg` 也能传上 OSS，若 bucket 是公共读且绑定自定义域名，就构成存储型 XSS / 恶意文件分发；
- `file.getBytes()` 把整个文件读进堆内存，10MB 限制下还可接受，但并发下会放大 GC 压力。

**修复**：扩展名白名单（jpg/jpeg/png/gif/webp）+ 校验 `Content-Type` 与文件头魔数 + 文件名兜底 + 建议改为 `file.getInputStream()` 流式上传。

### P1-4 违纪扣分不更新 `update_time`，且校验不完整

**位置**：[StudentServiceImpl.java:54-65](tlias-web-management/src/main/java/com/mww/service/impl/StudentServiceImpl.java#L54-L65)

```java
student.setUpdateTime(LocalDateTime.now());   // ← 只改内存对象，永远落不了库
studentMapper.violation(id, score);
```

`violation` 的 SQL 只自增 `violation_count` / `violation_score`，不写 `update_time`。因为列表默认 `order by update_time desc`，扣分后该学员不会冒到最前，用户以为没生效。另外：

- `score` 只校验了 `> 0`，没校验上限（比如 ≤ 100），可一次扣 9999 分；
- 为了校验存在性先 `getById` 再 `update`，多一次往返；直接看影响行数即可。

**修复**：SQL 里补 `update_time = #{updateTime}`（用 mapper 参数传），删除死代码。

### P1-5 操作日志只覆盖了 3 个接口，注释与实际行为不符

**位置**：[OperateLogAspect.java:62-66](tlias-web-management/src/main/java/com/mww/aop/OperateLogAspect.java#L62-L66)、[OperateLogAspect.java:106-124](tlias-web-management/src/main/java/com/mww/aop/OperateLogAspect.java#L106-L124)

### P1-6 班级 `status` 字段存在两套语义，接口返回不一致

**位置**：[ClazzMapper.xml:28-32](tlias-web-management/src/main/resources/com/mww/mapper/ClazzMapper.xml#L28-L32)、[ClazzMapper.xml:72](tlias-web-management/src/main/resources/com/mww/mapper/ClazzMapper.xml#L72)

`select` 用 `CASE` 实时计算中文状态（未开班/在读/已结课），`selectAll` 却直接读 `c.status` 原始列，`insert`/`update` 又把这个列写进去。同一个字段三种用法：

- `/clazzs` 返回 `"在读"`，`/clazzs/list` 返回 `"1"`（需核实该列是否为 tinyint）；
- 前端渲染状态标签时必然出现一处显示数字。

**修复**：确定唯一数据源。推荐**状态不入库**，全部由 `begin_date/end_date` 实时计算（`CASE` 抽成 `<sql>` 片段复用），删除 `insert/update/selectAll` 里的 `status`；否则改成字典表/枚举并统一返回中文。

### P1-7 唯一键冲突提示的解析方式极其脆弱

**位置**：[GlobalExceptionHander.java:17-25](tlias-web-management/src/main/java/com/mww/exception/GlobalExceptionHander.java#L17-L25)

```java
int i = message.indexOf("Duplicate entry");
String errMsg = message.substring(i);      // message 不含该串时 i = -1 → 抛 StringIndexOutOfBoundsException
String[] arr = errMsg.split(" ");
return Result.error(arr[2] + "已存在");     // 数组越界风险
```

在异常处理器里再抛异常，Spring 会走默认错误页，前端拿到 500 而不是「xx已存在」。而且强依赖 MySQL 报错文案，换了驱动版本或国际化就崩。

**修复**：用正则 `Duplicate entry '(.+?)' for key '(.+?)'` 兜底判空；或直接统一提示「数据已存在，请勿重复提交」，把细节打到日志。

### P2-2 `resultMap` 里列名拼写错误，密码映射静默失败

**位置**：[EmpMapper.xml:48](tlias-web-management/src/main/resources/com/mww/mapper/EmpMapper.xml#L48)

```xml
<result column="passwaord" property="password"/>
```

`passwaord` → `password`。这个 `resultMap` 带 `<collection>` 嵌套映射，MyBatis 默认 `autoMappingBehavior=PARTIAL` 对**含嵌套映射的结果集不做自动映射**，所以这一列永远映射不到，`GET /emps/{id}` 返回的 `password` 恒为 `null`。另外 `deptName` 也没在 resultMap 里声明，回显查询拿不到部门名。

**建议**：改对拼写，并把 `dept_name` 补进映射或改用 `JOIN` 后按别名 `deptName` 自动映射（配合 `resultType` + 一次查询经历，或 `select` 子查询）。

实际测试覆盖率 0。这是简历上最容易被追问的点（「你怎么保证改完不出问题？」）。

**建议**：至少补 `@MybatisTest` 的 Mapper 测试（分页、动态条件、批量插入）+ `@WebMvcTest` 的 Controller 测试（401、参数校验、异常分支）。10 个用例就能把故事讲圆。

---

### P2-6 没有建表脚本，项目不可复现

全仓库没有 `.sql` 文件。删库即失传：表结构、索引（如 `dept.name` 唯一键，否则 P1-7 的 DuplicateKey 根本不会触发）、初始化数据全靠本地 MySQL。新人接手第一步就卡住。

**建议**：提交 `db/schema.sql` + `db/data.sql`（或 Flyway/Liquibase 迁移脚本）。

---

### P2-7 缺少参数校验

`pom.xml` 没有 `spring-boot-starter-validation`，所有 `@RequestBody` 都没有 `@Valid`。可以提交空部门名、负薪资、`pageSize=1000000`（一次性拉全表）。

**建议**：

```java
@NotBlank(message = "部门名称不能为空")
@Size(max = 20)
private String name;
```

Controller 上加 `@Validated`，全局异常处理补 `MethodArgumentNotValidException` 分支；分页参数加 `@Max(100)`。

### P2-9 依赖版本需核实兼容性

- `java.version=25` + Spring Boot 3.5.15：属于比较激进的前沿组合，需确认 CI / 部署环境 JDK 一致，否则队友或服务器上直接跑不起来。
- `pagehelper-spring-boot-starter:1.4.7` 是面向 Spring Boot 2.x 的分支；Boot 3 官方推荐 2.x 系列。当前能跑不代表没问题（`PageHelper.startPage` 若未生效，`(Page<Emp>) empList` 会 `ClassCastException`）。
- `EMPTY` 式依赖写法（`<licenses/>`、`<developers/>`、`<scm/>` 全空）是 IDEA 生成模板残留，建议清理。

### P3 优化建议（有时间再做）

1. **`countStudentCountData` 硬编码班级名**（[StudentMapper.xml:130-141](tlias-web-management/src/main/resources/com/mww/mapper/StudentMapper.xml#L130-L141)）：`case when clazz_id = 1 then 'Java开发' ...` 班级一变统计就错。改成 `JOIN clazz GROUP BY c.name`。
2. **没有接口文档**：引入 `springdoc-openapi` + Swagger UI，30 个接口的手工联调成本立刻降下来。
3. **`GET /debug` 类残留**：[WebConfig.java:18-20](tlias-web-management/src/main/java/com/mww/config/WebConfig.java#L18-L20) 的 `System.out.println("===== WebConfig 已加载 =====")` 属于调试代码。
4. **JWT 密钥硬编码**（[JwtUtils.java:15](tlias-web-management/src/main/java/com/mww/utils/JwtUtils.java#L15)）：`SECRET_STRING` 写在源码里，且有效期固定 1 小时、无刷新、无退出登录（token 无法主动失效）。建议配置化 + 加 `jti` 黑名单或改用双 token。
5. **无 CORS / 无统一错误码**：目前靠前端 dev proxy；`Result` 用 `1/0` 而 HTTP 恒为 200，异常分支前端只能靠 `code` 判断，建议补一张错误码表。

## 五、一句话结论

**架构与骨架是合格的**：分层、统一响应、动态 SQL、JWT + ThreadLocal、AOP 审计都踩在点上，说明对 Spring 生态的理解是完整的。
**但缺少「防御性」和「一致性」**：密码裸奔、事务边界随意、写操作缺少前置校验、配置里留着教程痕迹。这些恰好是面试官区分「训练项目」和「能上手干活」的地方，也是这次改造最有价值的部分。
